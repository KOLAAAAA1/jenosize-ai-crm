⛨ Suggestion → Commit boundary
AI output and inbound LINE events are records, never silent side effects.

Nothing reaches the customer or becomes a confirmed CRM fact until a human approves it. AI results land as AiSuggestion (SUGGESTED); inbound LINE lands as Message (RECEIVED). A person clicks Accept or Approve — only then is a real Activity or an outbound Message written.

Key data flows

Four request paths that exercise the boundary above. Each is a graded flow in the assignment.

01LINE inbound message
LINE → /api/line/webhook → verify sig → dedupe → persist Message + WebhookEvent → map to lead → appears on timeline
02Ask AI on a lead
UI → /api/ai/copilot → build context → Claude (or fallback) → AiSuggestion SUGGESTED → shown → Accept writes Activity
03Approve & send LINE reply
draft reply → human Approve → LINE send (mock adapter when disabled) → Message SENT → retry-safe on failure
04Move a lead stage
board drag → /api/crm/leads/:id → update stage → write STAGE_CHANGE activity → timeline updates after hard refresh
